# 安全组配置指南

安全组是 ECS 实例的虚拟有状态防火墙，规则在**实例侧**生效，与 VPC 路由、
交换机网段是两套独立机制。理解「有状态」这一点能省掉一半配置：
放通入方向 SYN 之后，回包由连接跟踪自动放行，**不需要**再配一条出方向规则。

## 规则字段

| 字段 | 取值要点 |
|------|----------|
| 优先级 | 1（最高）到 100。数值越小越先匹配 |
| 策略 | 允许 / 拒绝。规则按优先级从小到大匹配，**第一条完整命中的规则决定结果**；优先级相同时拒绝优先于允许 |
| 协议类型 | TCP / UDP / ICMP / ALL；指定端口范围时必须是 TCP 或 UDP |
| 端口范围 | 单个端口写 `22/22`；区间 `8000/9000`；ALL 为 `-1/-1` |
| 授权对象 | IPv4 用 CIDR（`192.0.2.0/24`）；内网互通建议直接引用另一个安全组 ID |

入方向规则若一条都不存在，默认是**全部拒绝**；出方向默认**全部放行**。
这也是「新建安全组后 SSH 连不上」的标准答案。

## 常见放通场景

- **SSH**：TCP `22/22`，源写运维出口 IP 的 `/32`。不要写 `0.0.0.0/0`——公网扫描
  会在数分钟内命中，爆破成功后是整个实例的权限。
- **Web**：TCP `80/80`、`443/443`，源 `0.0.0.0/0`。这是少数确实需要对全网开放的端口。
- **Windows 远程桌面**：TCP `3389/3389`，同样限源 IP。
- **内网服务互访**：授权对象填「安全组 ID」而不是网段，实例在组内互通、组间隔离，
  扩缩容不用改规则。
- **健康检查与监控**：负载均衡与云监控探针需要放通对应端口，否则会出现
  「服务正常但 SLB 判定后端异常」。

## 配置误区

1. 把安全组当 ACL 用：先加了一条优先级 1 的拒绝，再叠加允许，结果允许永不生效。
   调试时按「优先级从小到大」逐条比对流量特征。
2. 只改安全组不改应用：sshd 或 nginx 监听在 127.0.0.1 时，任何安全组规则都救不了。
3. 多安全组场景下漏改：实例同时属于 sg-a 与 sg-b 时，两条链路都要放通同一端口，
   或者把规则集中到一个组、另一个组只保留必要端口。
4. ICMP 全禁导致误判：禁 ping 会让 `ping` 与部分探活脚本显示不可达，
   但 TCP 端口其实是通的。排查时先测端口再测 ICMP。

## 变更验证

改完规则立刻用 `nc -vz <IP> <PORT>` 验证端口级连通性，不要凭「看起来配好了」收尾。
需要留痕时开启安全组流日志（flow logs），它可以回答「这条流量被哪条规则放行/拒绝」。
规则不生效时先确认地域与实例 ID 一致——跨地域复制的安全组副本经常被误认为是原组。
