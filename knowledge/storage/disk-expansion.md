# 云盘扩容操作指南

云盘扩容是 ECS 运维里最容易「做了一半以为做完」的操作。控制台把磁盘从 40 GiB 改成 100 GiB 之后，实例里的文件系统仍然只有 40 GiB，`df -h` 不会有任何变化——这不是扩容失败，而是扩容只完成了第一步。理解「块设备层」和「文件系统层」的分界，是避免事故的关键。

## 在线扩容与离线扩容

阿里云云盘支持两种扩容方式，区别在于是否需要重启实例。

**在线扩容（推荐）**：实例处于运行中状态时直接提交扩容，无需停止业务。控制台选择目标云盘 → 扩容 → 勾选「在线扩容」→ 指定新容量 → 支付。扩容命令下发后，块设备层通常在一分钟内完成，但操作系统侧仍然看不到新空间，必须执行后面的「扩展分区与文件系统」步骤。在线扩容的容量上限受云盘类型限制，且不支持缩容。

**离线扩容**：需要先把实例停止（或先卸载云盘）再提交扩容。适用于两种场景：一是部分历史云盘类型不支持在线扩容；二是运维窗口本来就要求停机，希望一次性完成分区表调整以避免在线调整的风险。离线扩容后必须重启实例（或重新挂载），操作系统才会识别到新容量。

两种方式在「容量增大」这一点上完全等价，后续的文件系统扩展操作也相同。选择依据只有一个：业务能否接受停机。

## 扩容前必须创建快照

这是本指南最强调的一条。扩容本身不写数据，但它紧接着的分区与文件系统调整是直接改写分区表的操作，一旦填错设备名或参数，数据不可恢复。

正确做法：在控制台对该云盘创建一份快照，并**等待快照进度到达 100%**（不是「已创建」）。快照创建后，即使后续操作把分区表搞坏，也可以通过「用快照创建云盘」或「回滚云盘」恢复。回滚会丢弃快照之后的增量数据，这一点需要提前和业务方确认。

顺带检查：确认快照所属地域与云盘一致，跨地域快照不能直接回滚本盘。

## 确认块设备名与当前布局

不同实例规格的系统盘设备名并不统一，可能呈现为 `/dev/vda`、`/dev/xvda` 或 NVMe 形式的 `/dev/nvme0n1`。**不要凭记忆写设备名**，一律以实测输出为准：

```bash
lsblk
```

典型输出会显示磁盘容量已经变大（例如 100G），但其下的分区仍然只有 40G，剩余空间以「free space」形式挂在磁盘尾部。这个「磁盘 100G / 分区 40G」的不一致状态，正是需要手动扩展的证据。

同时记录文件系统类型，它决定了下一步用哪个工具：

```bash
df -Th /
```

`ext4` 用 `resize2fs`，`xfs` 用 `xfs_growfs`。用错工具不会破坏数据，但会报错并浪费排障时间。

## 扩展分区

如果分区尾部紧邻空闲空间，用 `growpart` 最直接（来自 `guestfs-tools` / `ec2-instance-connect` 相关包，多数阿里云公共镜像已内置）：

```bash
# 注意设备名与分区序号之间是空格，不是写 /dev/vda1
growpart /dev/vda 1
```

对 NVMe 设备同理：`growpart /dev/nvme0n1 1`。

`growpart` 只改分区表，不动文件系统，因此在未扩展文件系统前，`df -h` 仍然显示旧容量，这是预期行为。

若系统没有 `growpart`，可以用 `fdisk` 走「删除旧分区 → 用相同起始扇区重建一个更大的分区」的路径。**这条路径风险高**：起始扇区必须与原来完全一致，否则会丢失整个分区数据。除非明确知道自己在做什么，否则优先安装 `growpart`。

parted 用户注意：分区扩展后若提示需要 `parted` fix，按提示处理即可，不要盲目 `mklabel`。

## 扩展文件系统

分区扩好后，扩展文件系统才能真正被业务看到。

**ext4：**

```bash
resize2fs /dev/vda1
```

**xfs：**

```bash
xfs_growfs /
```

注意 `xfs_growfs` 接收的是**挂载点**而不是设备名，而 `resize2fs` 接收的是**设备名**。这是两者最容易记混的地方。

`xfs` 只能扩不能缩，且挂载点必须是当前正在挂载的状态。`resize2fs` 对已挂载的 ext4 可以直接在线扩展；若文件系统未挂载，则需指定设备名执行。

## 验证

```bash
lsblk
df -Th /
```

`df -Th` 的容量列应显示扩容后的值，且使用率相应下降。如果 `lsblk` 显示 100G 而 `df` 仍是 40G，说明分区扩展成功但文件系统扩展漏了，回到上一步补执行即可。

对于数据盘，验证时要用它自己的挂载点，不要只检查 `/`。

## 常见错误与排查

**「控制台扩完了但 df 没变」**——最常见，占实际问题的绝大多数。原因是把块设备层扩容当成了全流程。按「扩展分区 → 扩展文件系统」补齐两步即可，不是故障。

**只扩容了磁盘、分区表却看不到空闲空间**——如果旧分区不是磁盘的最后一个分区（例如同盘上还挂着别的分区），空闲空间被夹在中间，`growpart` 无法直接扩展。此时需要先调整分区布局，风险显著上升，建议改用「新购一块数据盘挂载」的方式替代。

**误以为可以缩容**——云盘不支持在线缩容。若确实需要更小容量，只能「创建快照 → 用快照创建一块更小的新云盘 → 更换系统盘/挂载新盘」，属于迁移而非缩容，要按迁移窗口规划。

**`growpart` 报 "no partition specified"**——参数写成了 `growpart /dev/vda1` 而非 `growpart /dev/vda 1`。设备和分区号是两个参数。

**多盘实例改错目标**——实例挂有多块数据盘时，务必先用 `lsblk` 按容量与挂载点核对设备名。把 `growpart` 打到错误的盘上不会立刻出事，但随后 `resize2fs` 就会在意外设备上执行。

**Windows 实例**——不走 growpart/resize2fs 路径，而是在「磁盘管理」里对卷执行「扩展卷」，前提是未分配空间紧邻在该卷右侧。

## 小结

一句话流程：**创建快照并等它完成 → 控制台在线扩容 → `lsblk` 确认盘已变大 → `growpart` 扩分区 → `resize2fs`/`xfs_growfs` 扩文件系统 → `df -Th` 验证**。缺任何一步，业务侧容量都不会变化。
