## 一、电梯陈述（三个长度，背熟第一个）

**30 秒版**：
> 我做了一个 Agent 持续改进平台 agent-up。企业把 Agent 上线只是开始，真正的难点是持续改进：
> 我把改进做成了工程化闭环——反馈进来由大模型自动归因到 Prompt/知识/工具/路由四个分区，
> 改配置走审批发布生成不可变版本快照，上线 7 天自动出效果报告，改坏了一键回滚。
> 模型层是可插拔的，公共云走百炼、专有云走 Apsara Stack 私有化，同一套闭环两种形态。

**2 分钟版**：30 秒版 + 补三点——
1. **为什么做**：客户现场发现 Agent 改进靠「开发改代码 + 拍脑袋」，没有审批、没有度量、没有回滚；
2. **怎么验证**：不是 PPT——268 个测试、26 个 Zod schema 全量校验、真实接入大模型（归因/摘要/试聊/发布 AI 评测都是 LIVE 调用）；
3. **商业视角**：卖模型是第一步，改进平台是让客户的模型消费「持续且可解释」的那层——用量有归因、改进有审批、效果有报告。

**5 分钟版**：2 分钟版 + 现场演示动线（One-Pager 的 5 步，压缩到 3 步：连通性 → AI 归因 → 试聊）。

## 三、预期追问与应答要点

**Q1：这不就是 prompt 管理后台吗，价值在哪？**
> 差异在闭环而不是表单：反馈→归因→审批→快照→效果报告→回滚是完整链路，
> 且有工程保证（状态机拒绝非法转移、不可变快照、append-only 审计）。
> 一句话：个人是「prompt 存代码里随手改」，企业是「每次改动都有审批记录和效果报告」。

**Q2：为什么不用百炼/现成平台直接做？**
> 定位互补不竞争：模型平台管「调用」，agent-up 管「改进运营」。
> 实际上 agent-up 的模型层就是可插拔的——演示环境真实接了 MiMo，换百炼只换网关配置。
> 对客户这句话更好用：「你今天的模型投资不浪费，改进层跨模型复用」。

**Q3：跟 LangSmith / Langfuse 这些比呢？**
> 它们重 trace 观测（L1 层），agent-up 重改进动作的治理（L2 层）：审批、版本、回滚、效果归因。
> 但 trace 层我也在落地：试聊 Playground 每次回复服务端落盘 trace → 👍/👎 打分 → 一键沉淀评测用例 →
> 发布前 AI 评测用快照回放全部用例——观测层与治理层开始打通（roadmap 已标本轮完成）。

**Q4：数据都是 mock 的，是不是玩具？**
> 主动分层回答：业务数据是 mock（页面全部标注 MOCK 徽标，这是演示形态的诚实边界）；
> 但三件事是真的——268 个测试真的跑、大模型真的在调（归因/摘要/试聊/发布 AI 评测 LIVE）、
> 工程纪律是真的（错误体系/校验/审计）。生产化里程碑明确：持久化→认证→CI。

**Q5：架构上最得意 / 最遗憾的一个决策？**
> 得意：四分区 + 不可变快照——让「分区级回滚」成为可能，改动影响面天然隔离。
> 遗憾：运行时用 JSON 文件存储换取了开发速度，换来并发写需要 actor 栈串行——
> 我知道代价，且 Prisma schema 已就绪，迁移路径是设计好的，不是欠着。
