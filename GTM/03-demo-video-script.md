# agent-up · 3 分钟演示视频脚本

> GTM 物料 #03 · 受众：企业客户 / 面试官（同一套录制，剪辑侧重见附录 D）· 版本：v1.0（2026-08-31）
> 用法：逐屏台词 + 操作动作，总时长 180 秒。所有路由、按钮文案均与演示应用核对一致（2026-08-31）；
> 数字引用 GTM/README 口径表，页面数值变化时先改口径表再改本脚本。

---

## 总原则

- 口播语速约 4 字/秒，台词全文约 680 字，留出操作等待与呼吸间隙。
- 每屏只讲一句话主张；让屏幕上的数字和徽标自己说话，台词不重复画面已可见的内容。
- LIVE / MOCK 徽标必须入镜——诚实边界是卖点，不回避。
- 台词中引用的实测数字（2,557ms · 45/73 tokens）是 2026-08-25 实测值，现场录制以实时返回为准，差距大就后期贴字幕条标注实测日期。

## 主脚本（180 秒 · 7 幕）

### S0 · 00:00–00:15 · 开场：工作台

| 项 | 内容 |
|----|------|
| 画面 | `/dashboard` 工作台，最近反馈与发布记录两块卡片在视野内 |
| 操作 | 登录（allengaller / 123）后停在工作台，光标缓划过反馈与发布卡片 |
| 台词 | Agent 上线只是开始，难的是持续改进：改不动、不敢改、说不清。接下来三分钟，我用一条完整的改进闭环，回答这三个问题。 |
| 预期证据 | 工作台「最近反馈 / 发布记录」卡片正常渲染 |

### S1 · 00:15–00:45 · 引擎是活的：模型服务

| 项 | 内容 |
|----|------|
| 画面 | `/maas`，「真实连通性测试（非 mock，实时调用模型）」卡片 |
| 操作 | 点「发起真实调用」，等待 2–3 秒出结果，光标指向时延与 tokens 数字 |
| 台词 | 先证明引擎是活的。点「发起真实调用」，平台实时请求推理服务——端到端 2,557 毫秒，输入 45、输出 73 个 tokens，模型身份实时返回。这一页其它产品矩阵标着 MOCK，只有这一块是 LIVE。哪些是真的，我们主动标清楚。 |
| 预期证据 | LIVE 徽标、mimo-v2.5-pro、时延与 tokens（实测参考 2,557ms · 45/73）、模型自我介绍引语 |

### S2 · 00:45–01:20 · 看得见：反馈 AI 归因

| 项 | 内容 |
|----|------|
| 画面 | `/feedback`，CRE 提交的安全组负面反馈（fb-001） |
| 操作 | 找到评价为「负面」的反馈 → 点「AI 归因」→ 等待「分析中…」出结果，光标划过归因 chip 与建议 |
| 台词 | 改进从反馈开始。这条负面反馈说：操作步骤正确，但对入方向、出方向的解释不清。点「AI 归因」，模型实时读这条反馈——定位到 Knowledge 分区，给出可执行的改法：在知识库补充方向性说明和常见端口放通示例。注意：归因只是缩小范围，改不改由人决定——这是治理，不是自动驾驶。 |
| 预期证据 | 「AI 归因」按钮 → 分析中… → AI 归因徽标 + 「归因 → KNOWLEDGE 分区」chip + 建议文案 |

### S3 · 01:20–01:55 · 改得动、立即验：Agent 详情页

| 项 | 内容 |
|----|------|
| 画面 | `/agents/ecs-assistant`，Prompt 分区编辑器 + 下方试聊 Playground |
| 操作 | 按归因建议修改 Prompt → 点「保存配置」→ 在试聊 Playground 输入「SSH 连不上 ECS，怎么排查？」发送 |
| 台词 | 按归因建议改配置。四个分区独立编辑，改提示词不动知识库。点「保存配置」，写入草稿——注意，这还不影响线上。下方试聊 Playground 已经用新配置：问它 SSH 连不上 ECS 怎么排查，回答第一步先检查安全组 22 端口。改完立刻验证，不等上线，不发版。 |
| 预期证据 | 「已保存到草稿」提示、试聊 LIVE 回答（模型实时生成，措辞以现场为准，参考：第一步先检查安全组是否放通 22 端口） |

### S4 · 01:55–02:30 · 管得住：发布审批

| 项 | 内容 |
|----|------|
| 画面 | `/releases`，刚才保存产生的待审批单 |
| 操作 | 点「查看变更」展开逐分区 diff → 点「AI 变更摘要」→ 点「通过」→ 弹窗点「通过并发布」 |
| 台词 | 改动不直接生效，走审批。展开「查看变更」：左边线上生效的版本，右边这次提交，逐分区 diff。「AI 变更摘要」把 diff 概括成人话——它甚至能识破「说了没改」的空操作。审批人核对后「通过并发布」，生成不可变版本快照：谁提交、谁审批、改了什么，审计日志一条不少。 |
| 预期证据 | 双栏 diff、AI 变更摘要出镜、确认弹窗「通过并发布」、新版本号生成 |

### S5 · 02:30–02:50 · 退得出：版本历史与回滚

| 预期证据 | 效果徽标（总数/负向/严重，数值现场读取，不预设）、回滚确认弹窗文案出镜 |

## 附录

### A. 录制前自检（沿用 02 第五节，加三条视频专属）

- [ ] `pnpm dev` 已起，`http://localhost:3000` 可访问，浏览器缩放 100%、隐藏书签栏
- [ ] `/maas` 先手动点一次「发起真实调用」确认凭据与网络 OK（这一条不过，S1 改用实测录屏素材）
- [ ] `/feedback` 存在 NEGATIVE 反馈（种子 fb-001 已含）；`/releases` 当前无历史遗留待审批单干扰画面
- [ ] 视频专属：录制分辨率 1080p 起、字体无模糊；关闭系统通知（勿扰模式）
- [ ] 视频专属：S3 的 Prompt 修改幅度提前排练——改动要小到 diff 一屏可读，大到试聊回答可感知差异
- [ ] 视频专属：一遍录口播一遍录屏幕容易互相拖累——建议先录屏幕（按本脚本操作），后配口播

### B. 时长弹性裁剪

| 版本 | 裁法 | 适用 |
|------|------|------|
| 3:00 完整版 | 全幕 | 客户会后留档 / 面试作品集 |
| 2:00 精简版 | 砍 S0（15s）+ S5 细节压到 10s + S6 压到 8s；S1 只留结果出镜 | 会前暖场 / 电梯场景 |
| 1:30 极简版 | 保留 S2 S3 S4（闭环三步），S1 收进 5 秒空镜+字幕「LIVE 调用已验证」 | 社交媒体 / 站内预览 |

### C. 失败预案（现场或录制中 LIVE 调用失败）

- **S1 探针失败**：页面自带「连通性测试未通过」错误态出镜，台词换：「这是平台的错误处理——每一步失败都有明确原因和下一步建议。」随后到附录 A 的实测素材兜底。
- **S2 归因 / S3 试聊失败**：页面提示引导到「模型服务」页做连通性探测——顺势口播一句「依赖模型服务的功能都有独立的失败路径，不静默、不假成功」；重试一次，仍失败则按 B 表极简版跳过。
- **S4 摘要失败**：页面提示「摘要失败不影响审批，diff 仍完整可读」——照念即可，这本身就是卖点。
