基于 Next.js App Router 的 RESTful 路由层，按资源路径划分：
- `GET /api/agents/[id]/versions`：列出某 Agent 的所有 Version（按 publishedAt 倒序），并通过 `getOrComputeEffectivenessReport` 对缺失且超 7 天窗口的版本惰性计算效能报告。
- `GET /api/agents/[id]/versions/[versionId]`：返回单个 Version 详情，含 agentId 归属校验。
- `POST /api/agents/[id]/rollback/[versionId]`：整版本回滚入口，委托 `createRollbackRelease` 一次性覆盖四个 active config 分区、写入 APPROVED release 并派生新 Version，区别于单分区 rollback。
所有写操作均通过 `withActor(resolveActor(request.headers))` 包裹以注入审计上下文；错误统一经 `handleApiError` 处理，成功响应经 `success` 包装。数据访问直接走 `@agent-up/db` 的 Prisma client，DTO 转换由 `toVersionResponse` 完成。
