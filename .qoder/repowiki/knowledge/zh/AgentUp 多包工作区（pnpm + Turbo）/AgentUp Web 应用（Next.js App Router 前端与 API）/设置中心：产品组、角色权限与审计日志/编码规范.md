- API route 统一以 `success(data, status?)` 包装响应，异常经 `handleApiError(err)` 转换后返回，形成一致的 `{ success, data?, error? }` 协议。
- 写入口先 `validateBody(request, schema)` 校验 Zod schema，失败直接返回 `validated.response`，成功再进入业务逻辑。
- 所有变更操作都包裹在 `withActor(resolveActor(request.headers), async () => { ... })` 中，并在内部调用 `requirePermission(resource, action)` 做 RBAC 校验。
- 每次持久化变更后调用 `recordAudit(actionCode, resourceType, resourceId, payload?)` 记录审计事件，动作码采用 `xxx.create/update/delete` 三段式命名。
- 客户端 Tab 组件遵循 loading/error/data 三态渲染：用 `Skeleton` 占位、`Alert tone="danger"` 展示错误并提供 onRetry、空数据时显示 `EmptyState`。
- 前端对两个独立接口（如 roles 与 permissions）使用 `Promise.all([...].then(r=>r.json()).catch(()=>null))` 分别捕获异常，避免一个失败导致另一个已取数据被清空。
