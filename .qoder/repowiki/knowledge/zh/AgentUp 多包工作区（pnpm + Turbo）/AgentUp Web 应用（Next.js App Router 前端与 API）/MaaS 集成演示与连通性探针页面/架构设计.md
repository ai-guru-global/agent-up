模块按 Next.js App Router 的 `app/(dashboard)/maas/`（客户端页面）与 `app/api/maas/`（服务端 Route Handler）两层组织：
- 页面层 `page.tsx` 是静态 mock 内容的主入口，通过 `<Section>` / `<Table>` / `<Mermaid>` 等 UI 组件渲染产品矩阵、路由流程图与四分区演进表；其中「连通性测试」与「用量」两个区块由同目录的 `connectivity-probe.tsx`、`usage-block.tsx` 两个 `'use client'` 子组件提供。
- API 层暴露两个 REST 端点：`GET|POST /api/maas/probe` 读取 LLM 配置并可选发起一次真实 chatCompletion 验证端到端连通性；`GET /api/maas/usage` 聚合试聊 Playground 产生的 trace 输出每 Agent 用量报告。
- 数据流方向单向：客户端组件 → `/api/maas/*` Route Handler → `@/lib/services/{llm-service,maas-usage-service}` → 外部 LLM 或 trace 存储；页面其余部分为纯静态 mock，仅在顶部探针与用量块处切换为 LIVE 数据。
- 依赖方向仅向外指向 `@/components/ui`、`../architecture/_components/ui` 与 `@/lib/**`，本模块内部不互相引用业务逻辑，保持页面与 API 解耦。
