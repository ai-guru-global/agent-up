模块由 Next.js App Router 的两层组成：
- 客户端页面 `apps/web/app/(dashboard)/releases/page.tsx` 是唯一的 UI 入口，使用 `"use client"`，通过 `fetch` 直接调用同域 API，并在本地完成状态筛选、分区 diff 计算（`computeDiff`）和 AI 评测结果渲染。
- 服务端路由位于 `apps/web/app/api/releases/`，遵循 REST 风格：`GET /api/releases` 分页列出 Release；`GET /api/releases/[id]` 返回含 `configSnapshot` 与 baseline 的详情供 diff 展示；`PUT /api/releases/[id]/review` 执行审批动作；`POST /api/releases/[id]/ai-review` 触发发布前 AI 评测；`POST /api/releases/[id]/summary` 调用 LLM 生成变更摘要（无状态、不落库）。

依赖方向单向向外：UI → Route Handler → `@agent-up/db`（Prisma）+ `@/lib/services/*`（`release-service`、`agent-service`、`ai-review-service`、`llm-service`）+ `@/lib/context`（`withActor`/`resolveActor` 注入审计身份）。业务逻辑集中在 service 层，Route Handler 仅做参数解析、校验（`validateBody` + zod schema）、错误包装（`handleApiError`）与统一响应（`success`）。Baseline 版本计算（取 release 对应 version 的前一个版本或最新已发布版本）在 GET detail 与 summary 两个 handler 中重复实现，是潜在的抽取点。
