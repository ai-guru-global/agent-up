模块由两部分组成：
- 客户端页面 `apps/web/app/(dashboard)/settings/page.tsx` 是一个 `'use client'` 单文件组件，内部按 `groups | roles | audit` 三个 tab 渲染 `ProductGroupsTab` / `RolesTab` / `AuditLogsTab`，通过原生 `fetch` 直接调用同域 `/api/settings/*` 接口，使用 `@/components/ui` 中的 `Alert` / `Skeleton` / `EmptyState` / `Field` / `Input` 等原子组件完成表单与列表。
- API 层位于 `apps/web/app/api/settings/`，遵循 Next.js Route Handlers 约定，每个子目录对应一个资源（`product-groups`、`roles`、`permissions`、`audit-logs`），`roles/[id]` 通过动态段支持 PUT/DELETE。

依赖方向单向向外：API route → `@agent-up/db` (Prisma) + `@/lib/utils` (`success`/`validateBody`/`handleApiError`) + `@/lib/schemas` (Zod schema) + `@/lib/context` (`withActor`/`resolveActor`) + `@/lib/services/rbac` (`requirePermission`) + `@/lib/services/audit-service` (`recordAudit`/`listAudit`) + `@/lib/errors`。所有写操作统一在 `withActor(resolveActor(...))` 包裹内执行 RBAC 校验后再落库，并通过 `recordAudit` 记录审计事件；读操作（如 `GET /api/settings/roles`、`GET /api/settings/product-groups`）不强制鉴权，仅返回数据。
