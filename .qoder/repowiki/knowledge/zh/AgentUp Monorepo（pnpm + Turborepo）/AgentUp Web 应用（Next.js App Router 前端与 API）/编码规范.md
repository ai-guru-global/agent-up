- API 路由采用 Next.js App Router 的 route.ts 文件组织，URL 路径与 app/api 目录结构一一对应，参数段使用 [id] 语法。
- 客户端页面与 API 路由成对出现于同一业务目录（如 agents、skills、wiki、releases、feedback、settings、maas），共享 Zod schema 与错误类型。
- 跨域复用逻辑集中在 lib/ 下（auth-token、context、errors、schemas、utils、versioning、diff、retrieval-bm25），页面与路由不直接实现通用能力。
- 展示型基础组件收敛在 components/ui/（primitives、modal、form、status），业务页面通过该目录而非内联 Tailwind 拼装样式。
- 单元测试使用 Vitest 直接 import route.ts 与 lib 模块，测试文件与源码同目录放在 __tests__/ 子目录，覆盖率输出至 coverage/。
