模块按职责切分为若干独立文件，被 apps/web 下的 route handler 与 services 层共同消费：
- 身份与上下文：`auth-token.ts` 用 `node:crypto` 的 HMAC-SHA256 签发 v1.<base64url>.<sig> 格式的会话令牌；`context.ts` 通过 `AsyncLocalStorage` 把经 `resolveActor` 解析出的 Actor 注入到异步调用链中，签名令牌失败时绝不回落到明文 `x-actor-*` 头。
- 安全原语：`password-hash.ts` 基于 scrypt 实现自描述存储格式 `scrypt$N$r$p$salt$hash`，并对成本参数做上界钳制以防内存攻击。
- 数据契约：`schemas.ts` 集中所有 Zod schema（Agent / Feedback / Skill / Wiki Vault & Page / Role / Permission / ProductGroup / Eval Case 等），并导出对应的 `z.infer` 类型供上层使用。
- 错误模型：`errors.ts` 定义 `AppError` 及其 NOT_FOUND / VALIDATION / CONFLICT / AUTHORIZATION / INTERNAL 子类，配合 `toErrorBody` 将任意 thrown 值映射为结构化 HTTP 响应体。
- 领域工具：`diff.ts` 提供 JSON diff，`versioning.ts` 根据分区变更集合计算 SemVer 版本号，`retrieval-bm25.ts` 是零 Node 依赖的 BM25-lite 算法层，可同时在服务端与浏览器 demo 轨复用。
- 业务服务聚合：`services/` 下每个文件对应一个领域（agent、feedback、skill、wiki、trace、eval-case、rbac、release、retrieval 等），统一通过 `getActor()` 获取审计署名，并通过抛出 `AppError` 子类向上报告错误。
- 测试数据：`data/test-db.ts` 提供测试数据库种子。
依赖方向单向向下：services → context/auth-token/schemas/errors；顶层文件之间仅 `auth-token.ts` 反向 import `Actor` 类型以解耦。
