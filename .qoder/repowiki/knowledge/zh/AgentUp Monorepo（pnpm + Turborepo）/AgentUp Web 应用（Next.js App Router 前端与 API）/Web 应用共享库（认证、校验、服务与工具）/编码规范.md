- 对外暴露的请求体一律先经 `schemas.ts` 中的 Zod schema 校验，再在 service 层进行业务规则检查，避免手写 if/else 判断。
- service 层不直接返回 HTTP 状态码，而是抛出 `errors.ts` 中定义的 `AppError` 子类（NotFound/Validation/Conflict/Authorization），由 API 层统一映射。
- 需要审计署名的写操作通过 `context.ts` 的 `getActor()` 获取当前 Actor，不再散落硬编码 "system" 字符串。
- 安全相关常量（如 scrypt 成本参数 N/r/p、session TTL、token 前缀）集中在各自模块顶部作为常量，便于调整与审计。
- 对不可信输入的验证一律采用 fail-closed 语义：任何异常、格式错误或越界值都返回 null/false，而不是抛错或静默降级。
