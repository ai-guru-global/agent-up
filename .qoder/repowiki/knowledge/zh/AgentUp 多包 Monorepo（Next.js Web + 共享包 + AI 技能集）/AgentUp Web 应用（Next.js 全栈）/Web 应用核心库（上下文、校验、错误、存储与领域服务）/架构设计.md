模块按职责分层组织：
- `context.ts` 通过模块级栈实现请求级 Actor 上下文，由 route handler 用 `withActor` 包裹 service 调用，service 层统一通过 `getActor()` 获取当前操作者。
- `schemas.ts` 集中定义所有 API 入参的 Zod schema 并导出对应 TypeScript 类型，作为前后端共享的契约。
- `errors.ts` 定义 `AppError` 基类及 `NotFoundError`/`ValidationError`/`ConflictError`/`AuthorizationError` 子类，配合 `toErrorBody` 将异常映射为结构化 HTTP 响应。
- `utils.ts` 提供 `success`/`error`/`handleApiError`/`validateBody`/`parsePagination` 等路由通用工具。
- `data/store.ts` 封装基于 `fs` 的 JSON 文件 CRUD，通过 `_setDataDir` 暴露测试隔离能力；实体统一带 `id`/`createdAt`/`updatedAt` 字段。
- `services/` 下每个领域一个 service 文件（agent/feedback/release/skill/wiki/audit），仅依赖 store、context、errors、diff/versioning，不直接依赖 Next.js。
- `diff.ts` 和 `versioning.ts` 是纯函数工具，被多个 service 复用，分别负责 JSON diff 与 SemVer 计算。
依赖方向单向：services → store/context/errors/diff/versioning，上层 route handler 通过 utils 组装响应。
