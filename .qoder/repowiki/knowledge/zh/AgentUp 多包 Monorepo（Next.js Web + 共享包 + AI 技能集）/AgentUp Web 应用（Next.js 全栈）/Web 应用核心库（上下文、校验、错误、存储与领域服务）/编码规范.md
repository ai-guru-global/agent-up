- 所有 API 入参通过 `schemas.ts` 中的 Zod schema 校验，使用 `utils.validateBody` 统一返回 `{ ok, data }` 或 422 响应。
- 业务异常统一抛 `AppError` 子类（NotFound/Validation/Conflict/Authorization），由 `utils.handleApiError` + `errors.toErrorBody` 映射为带 code/status 的结构化响应。
- Service 层通过 `getActor()` 获取当前操作者，不再散落硬编码 "system"，写操作同时调用 `recordAudit` 记录审计日志。
- 实体统一包含 `id`（`store.generateId()` 生成）、`createdAt`、`updatedAt` 时间戳字段，删除采用软删除（status 改为 ARCHIVED）。
- 配置分区（prompt/knowledge/tools/routing）变更通过 `computeJsonDiff` 计算差异并写入 `config-changes/<id>.json`，版本号由 `bumpVersion` 基于 changedPartitions 自动计算。
