## 引言
AgentUp（Agent 改进平台）是一个面向专有云工单场景的 Agent 持续改进管理平台。它的核心目标是：让各产品组在同一个平台上维护和改进各自的 Agent 配置，包括 Prompt、Knowledge、Tools 与 Routing；每次改动通过发布审批流程生成不可变版本快照，并支持分区级或整版本回滚。平台以「三层 Loop」为设计理念，把 Agent 运行时交互、产品改进闭环和跨 Agent 智能进化按时间尺度分层，从而让「模型可换，闭环不变」。

从技术角度看，AgentUp 是 Next.js 16 + TypeScript + Tailwind CSS 4 + Prisma + SQLite 的全栈 Monorepo 应用，使用 Turborepo 与 pnpm workspaces 组织代码，并通过 Chrome 插件 PoC 打通试聊反馈收集入口。它既可作为内部产品迭代平台，也可作为客户现场演示与面试展示工具，直观呈现「与客户一起持续迭代 Agent」的完整闭环。

## 核心组件
AgentUp 的核心能力围绕「Agent 四分区配置 + 发布审批流 + 反馈闭环 + 知识库与技能 + MaaS 集成展示」展开。

| 核心组件 | 职责 | 对应实现位置 |
|---------|------|-------------|
| Agent 四分区编辑器 | 编辑 Prompt、Knowledge、Tools、Routing，保存草稿，不改线上配置 | `apps/web/app/(dashboard)/agents/` |
| 发布审批流 | 提交 Release、自动 diff、SemVer、审批后生成 Version 快照 | `apps/web/app/api/releases/`、`lib/services/release-service.ts` |
| 回滚机制 | 分区级回滚与整版本回滚，均生成新版本 | `apps/web/app/api/agents/[id]/config/[partition]/rollback`、`rollback/[versionId]` |
| 反馈闭环 | 反馈录入 → AI 归因 → 定位分区 → 改进 → 发布验证 | `apps/web/app/(dashboard)/feedback/`、`lib/services/feedback-service.ts` |
| 知识库 Wiki | Vault + Page 两级知识管理，BM25-lite 检索 | `apps/web/app/(dashboard)/wiki/`、`lib/services/wiki-service.ts` |
| Skills 管理 | 可复用技能组件与 Agent 绑定 | `apps/web/app/(dashboard)/skills/`、`lib/services/skill-service.ts` |
| 设置与 RBAC | 产品组、角色、权限、审计日志 | `apps/web/app/(dashboard)/settings/`、`lib/services/audit-service.ts` |
| MaaS 集成展示 | 公共云与专有云模型矩阵、路由策略、用量聚合 | `apps/web/app/(dashboard)/maas/` |
| LLM 网关 | 小米 MiMo 真实接入，统一超时与结构化错误 | `lib/services/llm-service.ts` |

这些组件共同构成一个「反馈驱动配置改进」的平台闭环：用户或系统产生反馈，平台辅助归因，产品组修改 Agent 配置，审批通过后上线，效果报告衡量改进价值。

## 架构总览
当前运行形态是「数据库即真相源」：浏览器通过 Next.js App Router 访问页面，页面调用 `/api/*` 路由，路由层只做协议适配、参数校验和错误映射，真实业务逻辑下沉到 `lib/services` 中的服务层，存储读写统一走 Prisma Client，外部 LLM 调用统一经过 LLM 网关。

```mermaid
flowchart LR
Browser["浏览器 · Next.js App Router 页面"] --> Routes["API 路由层<br/>Zod 校验 · 结构化错误 · Actor 上下文"]
Routes --> Services["服务层<br/>agent / release / feedback / skill / wiki<br/>trace / eval-case / ai-review / effectiveness / audit"]
Services --> DB[("SQLite + Prisma")]
Services --> LLM["LLM 网关<br/>小米 MiMo"]
LLM --> Model["大模型服务"]
Services -. "后续预留" .-> Storage[("MinIO / S3")]
```

**图表来源**

这个架构的关键约束是：API 路由不承载复杂业务逻辑；所有写操作应伴随审计；所有入参由 Zod schema 校验；所有枚举值在 SQLite 下用字符串列 + 运行时校验表达；JSON 字段通过 `@agent-up/db` 的 JSON 打包函数安全存取。

### 三层 Loop 设计理念
AgentUp 的设计骨架不是某个具体 Agent 框架，而是「不同时间尺度的改进循环」。L1 是 Agent 运行时与用户的即时交互环，L2 是产品组基于反馈改进 Agent 的配置环，L3 是跨 Agent 的智能进化环。平台重点落地的是 L2，并为 L3 预留扩展点。


### 发布审批与版本快照流程
发布流程是 AgentUp 治理能力的核心：编辑配置 → 提交发布 → 自动 diff 与语义化版本号 → 审批 → 生成不可变版本快照 → 可选回滚。

## 性能与工程特性
AgentUp 的工程特性与其产品目标一致：强调可观测、可回溯、可回滚、可测试。

| 工程特性 | 说明 | 相关位置 |
|---------|------|---------|
| 结构化错误 | AppError 层级映射 HTTP 状态码，消除字符串匹配 | `lib/errors.ts` |
| 全量参数校验 | 30 个 Zod schema 覆盖 API 入参 | `lib/schemas.ts` |
| Actor 上下文 | 解析请求头身份，为 NextAuth 留接口 | `lib/context.ts` |
| 审计日志 | 所有写操作 append-only | `lib/services/audit-service.ts` |
| 真 SemVer | 按分区变更范围计算 patch/minor | `lib/versioning.ts` |
| 反馈状态机 | 非法状态转移被拒 | `feedback-service.ts` |
| Prisma 持久化 | 全业务运行时走数据库 | `packages/db` |
| MOCK 标注规范 | mock 数据显式标注，真实调用标 LIVE | 多处 UI 与注释 |
| LLM 网关 | env 凭据零硬编码，统一超时 | `lib/services/llm-service.ts` |
| 测试规模 | 371 个测试，35 个测试文件 | `apps/web/app/api/__tests__/` |

这些特性共同降低 Agent 配置管理的风险：改 Prompt 不只是改一段文字，而是进入版本、审计、审批、回滚、效果报告的治理体系。

### 初始化数据库
AgentUp 当前使用 SQLite 单文件持久化，无需 Docker 守护进程。推荐顺序：
1. 生成 Prisma Client：`pnpm db:generate`
2. 部署迁移建表：`cd packages/db && npx prisma migrate deploy`
3. 灌入种子数据：`pnpm db:seed`

### 启动开发服务器
```bash
pnpm dev
```
然后访问 `http://localhost:3000`。

## 常见问题与排错

### 是否需要启动 PostgreSQL 或 MinIO？
不需要。当前存储为 SQLite 单文件，开发前只需完成 Prisma 生成、迁移和种子即可。

### 没有配置 LLM 凭据会怎样？
真实 LLM 集成点会返回 503，并在页面给出明确提示；其余功能不受影响。

### 测试会不会污染开发数据库？
不会。测试通过 `_resetDb` 清库后连接本地 SQLite 文件，并发 worker 使用独立 `.db` 文件，互不干扰。

### 如何重置演示数据？
执行 `pnpm db:seed`，种子脚本会先清空业务表再灌入种子数据。

### 演示账号是什么？
演示账号为邮箱 + 口令组合，来自 seed 预置数据，登录后拥有 mock 管理员权限。

## 结论
AgentUp 不是一个简单的 Agent 配置编辑器，而是一个围绕「三层 Loop」构建的 Agent 持续改进平台。它把 Prompt、Knowledge、Tools、Routing 这些通常散落在不同地方的 Agent 资产，收敛到统一的四分区模型中，并用 Release、Version、审计、回滚、效果报告和反馈闭环把它们串起来。

对初学者来说，AgentUp 提供了一个理解「Agent 改进不只是调模型」的入口：真正决定 Agent 质量的，往往是模型之外的 Prompt、Context、Harness、Loop 和 Graph。对有经验的开发者来说，AgentUp 的价值在于把行业经验中的 Harness 与 Loop 工程纪律，应用到 Agent 配置的迭代流程上，形成可测试、可审计、可回滚、可度量的产品能力。
