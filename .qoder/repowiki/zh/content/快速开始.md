## 简介
AgentUp 是一个面向 Agent 持续改进的管理平台，支持 Prompt、Knowledge、Tools、Routing 四分区编辑、版本发布审批、回滚、反馈闭环、效果报告、RBAC 审计日志，以及真实 LLM 接入。当前仓库使用 SQLite 单文件作为数据库，无需 Docker 或外部数据库服务即可本地运行；同时提供纯静态 Demo 构建能力，便于无服务端托管展示。

## 安装与数据库初始化
### 第一步：安装依赖
在项目根目录执行：

```bash
pnpm install
```

该命令会安装 Turborepo、Next.js、Prisma、测试框架等全部依赖。

### 第二步：生成 Prisma Client
```bash
pnpm db:generate
```

该命令会读取 `packages/db/prisma/schema.prisma` 并生成类型安全的 Prisma Client。

### 第三步：部署数据库迁移
```bash
cd packages/db && npx prisma migrate deploy
```

该命令会在 SQLite 文件中创建业务表结构。

### 第四步：灌入演示种子数据
```bash
pnpm db:seed
```

该命令会写入演示所需的用户、Agent、反馈、角色等初始数据。

### 完整一键流程
如果你希望按顺序执行上述步骤，可依次运行：

```bash
pnpm install
pnpm db:generate
cd packages/db && npx prisma migrate deploy
pnpm db:seed
```

完成后，数据库已就绪，可直接进入开发模式。

## 环境变量配置
本项目的环境变量主要涉及三类：数据库连接、LLM 凭据、认证密钥。

### 必需环境变量
| 变量名 | 用途 | 是否必需 | 说明 |
|--------|------|----------|------|
| `DATABASE_URL` | 数据库连接串 | 开发/测试必需 | SQLite 单文件连接串，例如指向 `dev.db` |
| `AUTH_SECRET` | 会话令牌签名密钥 | 生产必填 | HMAC-SHA256 签名密钥；开发可缺省但审计署名可能为匿名 |
| `MIMO_API_KEY` | 小米 MiMo LLM 凭据 | 可选 | 未配置时 LLM 相关端点返回 503，其余功能正常 |

### 可选环境变量
| 变量名 | 用途 | 默认值或说明 |
|--------|------|--------------|
| `MIMO_BASE_URL` | Token Plan Base URL | 默认中国集群地址 |
| `MIMO_MODEL` | 模型 ID | 默认 `mimo-v2.5-pro` |
| `AUTH_SESSION_TTL_HOURS` | 会话有效期 | 默认 24 小时 |
| `AUTH_TRUST_ACTOR_HEADERS` | 是否信任明文 actor 请求头 | 非生产默认采纳，生产默认拒绝 |

### 环境变量位置
- `apps/web/.env`：Next.js 应用运行时环境变量
- `packages/db/.env`：Prisma 迁移、种子与数据库工具使用的环境变量

如果缺少 `.env.example`，请根据 README 中的环境变量说明自行创建对应文件，至少填写 `DATABASE_URL`、`AUTH_SECRET`，如需真实 LLM 则补充 `MIMO_API_KEY`。

## 演示模式说明
AgentUp 支持两种运行形态：

| 形态 | 启动方式 | 特点 |
|------|----------|------|
| 本地全栈 | `pnpm dev` | 真实 Next.js API 路由 + SQLite 持久化，可选真实 LLM |
| 纯静态 Demo | `cd apps/web && pnpm build:demo` | 浏览器内存 mock API，产物输出到 `out/`，可托管到静态 CDN |

### 静态 Demo 构建
```bash
cd apps/web && pnpm build:demo
```

该命令等价于设置 `DEMO_EXPORT=1` 后执行 Next.js 构建，产物位于 `apps/web/out/`。该目录默认被忽略，适合临时导出演示站点。

### 演示模式行为
- 前端通过拦截同源 `/api/*` 请求，使用内存态镜像 API 响应形状
- 刷新页面会重置内存状态
- 演示模式下不需要数据库，也不依赖真实 LLM
- 演示入口仍可通过浏览器访问构建后的静态站点

## 故障排查常见问题解答

### Q1：需要先启动 PostgreSQL 或 MinIO 吗？
不需要。项目当前使用 SQLite 单文件数据库，无需 Docker 或外部数据库服务。只需完成 Prisma 迁移与种子数据即可。

### Q2：没有配置 `MIMO_API_KEY` 怎么办？
未配置时，真实 LLM 相关端点会返回 503，并在页面给出明确提示。其他功能不受影响。如需体验真实 LLM，请在 `apps/web/.env` 中配置 `MIMO_API_KEY`。

不会。每个测试在执行前会清理业务表并注入自身测试数据，测试结束后互不干扰。若需恢复演示数据，重新执行 `pnpm db:seed` 即可。

### Q6：为什么 `pnpm dev` 无法启动？
常见原因包括：
- Node.js 版本低于 20
- pnpm 版本低于 9
- 未执行 `pnpm install`
- 未执行 `pnpm db:generate`
- `DATABASE_URL` 未配置或路径错误
- 端口 3000 被占用

建议按“前置条件 → 安装 → 数据库初始化 → 启动开发环境”的顺序重新执行。

## 总结
对于新用户，最简成功路径如下：

1. 确认 Node.js >= 20、pnpm >= 9
2. 执行 `pnpm install`
3. 执行 `pnpm db:generate`
4. 执行 `cd packages/db && npx prisma migrate deploy`
5. 执行 `pnpm db:seed`
6. 执行 `pnpm dev`
7. 打开 `http://localhost:3000`，使用演示账号登录

如需纯静态演示，可在完成依赖安装后执行 `cd apps/web && pnpm build:demo`，并将 `apps/web/out/` 托管到任意静态站点服务。
